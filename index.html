Qu'est-ce que le versionning ?

Le versionning (ou contrôle de version) est un système qui enregistre les modifications apportées à un ou plusieurs fichiers au fil du temps, afin de pouvoir retrouver des versions spécifiques ultérieurement.

📈

Suivi des changements

Chaque modification est enregistrée avec un historique détaillé : qui a modifié quoi, quand et pourquoi, via des messages de commit.

🔁

Retour en arrière

En cas d'erreur ou de bug, il est possible de revenir à une version antérieure stable du projet en quelques secondes.

👥

Collaboration

Plusieurs développeurs peuvent travailler simultanément sur le même projet sans écraser le travail des autres, grâce aux branches et aux fusions.

🔒

Sécurité

Un dépôt centralisé (ou distribué) protège contre la perte de données et permet de sauvegarder régulièrement l'état du projet.

Historique du versionning

De la gestion manuelle des fichiers aux systèmes distribués modernes : l'évolution du contrôle de version.

Fichiers copiés manuellement

Années 1970

Les développeurs copient manuellement leurs fichiers avec des suffixes (ex. projet_final_v2.txt). Méthode simple mais source d'erreurs et de confusion.

SCCS & RCS

1972 – 1982

SCCS (Source Code Control System) et RCS (Revision Control System) introduisent les systèmes locaux de gestion de versions, sur un seul ordinateur.

CVS

1990

CVS (Concurrent Versions System) apporte le premier système centralisé pouvant gérer le travail de plusieurs développeurs sur un serveur central.

SVN (Subversion)

2000

Subversion améliore CVS avec des commits atomiques, des révisions numérotées mondialement et une meilleure gestion des répertoires.

Git

2005

Créé par Linus Torvalds pour le noyau Linux, Git est un système distribué : chaque développeur possède une copie complète du dépôt.

GitHub, GitLab & Bitbucket

2008 – aujourd'hui

L'émergence des plateformes d'hébergement de dépôts Git démocratise la collaboration, les pull requests et l'intégration continue.

Pourquoi versionner votre code ?

Les bénéfices concrets d'adopter un système de contrôle de version dans vos projets.

📚

Historique complet

Conservez la trace de chaque modification avec possibilité de comparer, annoter et comprendre l'évolution du code.

🔄

Branches & expérimentation

Testez de nouvelles idées sur des branches séparées sans risquer de casser la version stable du projet.

🗺

Restauration rapide

Restaurez instantanément n'importe quelle version antérieure grâce aux commits et aux tags de version.

🎯

Release management

Marquez des versions stables (v1.0, v2.1.3...) avec des tags pour un déploiement et un suivi de cycle de vie clairs.

✅

Intégration continue

Automatisez les tests et déploiements à chaque push grâce à l'intégration avec des pipelines CI/CD.

👮

Responsabilité & audit

Identifiez précisément quel auteur a introduit une modification, facilitant la relecture de code et l'audit.

Les types de systèmes de version

Trois grandes architectures existent pour organiser le contrôle de version.

🖥

Systèmes locaux

Comme RCS, ils stockent les versions sur l'ordinateur local. Un seul utilisateur, une seule machine. Simple mais limité.

🔌

Systèmes centralisés

Comme CVS et SVN, un serveur central stocke toutes les versions. Les clients téléchargent les fichiers pour travailler, mais dépendent du serveur.

📦

Systèmes distribués

Comme Git et Mercurial, chaque client dispose d'une copie complète du dépôt. Résilient, rapide et idéal pour la collaboration moderne.

Git & les branches

Visualisation du flux de travail classique avec Git : le tronc principal (main) et les branches de développement qui s'y fusionnent.

Branche principale (main) Branche de fonctionnalité Branche expérimentale
🔗

Commit

Un instantané (snapshot) de l'état du projet à un instant donné, accompagné d'un message descriptif.

📦

Branch

Une ligne de développement indépendante qui diverge de la branche principale pour ajouter des fonctionnalités.

🔀

Merge

L'opération qui fusionne les modifications d'une branche dans une autre, en résolvant les éventuels conflits.

🎯

Tag

Un marqueur immuable sur un commit spécifique, utilisé pour identifier les versions de release (v1.0, v2.0...).

Les commandes Git essentielles

Un aperçu des commandes fondamentales pour débuter avec Git dans votre terminal.

git init
Initialise un nouveau dépôt Git dans le répertoire courant.
git clone
Copie un dépôt distant (ex. GitHub) vers votre machine.
git status
Affiche l'état des fichiers : modifiés, indexés, ou non suivis.
git add
Ajoute des fichiers à la zone de staging (index) avant le commit.
git commit -m "message"
Enregistre un instantané des fichiers indexés avec un message.
git branch
Crée une nouvelle branche de développement.
git checkout
Bascule sur une autre branche ou restaure des fichiers.
git merge
Fusionne une branche dans la branche courante.
git push
Envoie les commits locaux vers le dépôt distant.
git pull
Récupère et fusionne les modifications du dépôt distant.
git log --oneline
Affiche l'historique des commits de façon compacte.
git tag v1.0
Marque un commit avec une étiquette de version.
